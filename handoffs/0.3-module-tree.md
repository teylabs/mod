## Behaviour and interfaces for downstream lanes

`Layout::frontend(pages: ..., components: ..., css: ..., views: ..., pageName: ...)` accepts all arguments optionally. Omitted values preserve the current configuration. `extends()` copies it; inherited tokens and customized `path()` anchors resolve with class placement. Explicit page overrides preserve their own casing.

`CompiledLayout::frontend()` returns project-relative templates with five keys: `pages`, `components`, `css`, `views`, `page_name`. All are nullable on an undeclared custom layout. Built-in page patterns use the layout's actual dimension name (`{module}::{path}` for modules, `{domain}::{path}` for DDD). For isolated compilation, `frontend($stack)` applies the app's page casing. The active container layout already has that casing applied by the provider, so its callers simply use `frontend()`.

`Stack` is bound in the application container. `inertia()` returns `vue`, `react` or `null`; `typescript()` checks for `tsconfig.json`; `pagesPath()` reports `resources/js/pages` or `resources/js/Pages` by examining actual directory entry spelling. Dependencies and devDependencies are checked; missing or malformed package JSON yields no adapter. It never writes or installs anything.

Built-ins declare namespace-free roots `resources-js`, `resources-components`, `resources-css`, `resources-views`, and `routes`. Frontend overrides relocate their associated roots. Modules and features use their group folder; slices use the full slice folder; DDD uses `app/Modules/{domain}`; Laravel and type-first use the project resources/routes folders. `CompiledLayout::isPlainFilePath()` recognizes plain-file roots, including nested groups and portable separators. Discovery filters these files before reverse mapping or class lookup, for both filesystem walking and a host-supplied candidate source. Namespace-free roots are omitted by the existing autoload mapping code.

HTTP changes: modules moves controller/request/middleware/resource under `Http/`; DDD moves application controller/request/middleware and leaves domain `Resources/` unchanged. Features already had `Http/`; slices already had it except its fixed `Request.php`, which now goes under the slice's `Http/Requests/`. Laravel and type-first HTTP placements are unchanged. Every other file type's placement is pinned against the older snapshot.

Case checks compare declared roots, class folders and their ancestors at compilation, on every OS and before any files exist. The resource collision message is:

```text
app/Modules/{module}/Resources and app/Modules/{module}/resources differ only by case. To keep API resources in Resources/, move the frontend root with ->frontend() to ui/.
```

This wording and the revised U1 snippet follow the lead's clarification in this session. Other case-only folder collisions end with `Move one of them.`
